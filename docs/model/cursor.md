在 Cursor 中，Agent、Plan、Debug、Ask 是四种核心的 AI 交互模式，它们在权限、行为和适用场景上有着本质区别，分别对应“执行者”、“规划师”、“排障专家”和“技术顾问”四种角色。

以下是它们的核心区别：

核心区别概览

| 维度 | Ask 模式 | Plan 模式 | Debug 模式 | Agent 模式 |
| :--- | :--- | :--- | :--- | :--- |
| 核心定位 | 技术顾问：解答问题，解释代码，不修改任何内容。 | 架构师：设计方案，梳理逻辑，生成计划但不执行。 | 排障专家：分析错误、定位 Bug，基于运行时证据诊断问题。 | 自动驾驶助手：自主分析、修改、执行，完成完整任务。 |
| 是否修改代码 | ❌ 从不修改代码 | ❌ 从不修改代码 | ❌ 不直接修改代码（但可建议修改） | ✅ 可自主修改、创建、删除多个文件 |
| 是否读取项目 | ❌ 仅在你明确 @ 它时查看当前代码 | ✅ 查看当前选中代码或文件 | ✅ 扫描整个项目，分析上下文和日志 | ✅ 深度扫描整个项目，理解结构与依赖 |
| 是否运行命令 | ❌ 不运行 | ❌ 不运行 | ❌ 不运行 | ✅ 可执行终端命令（如 `npm install`），需你确认 |
| 工作方式 | 单轮问答，即时响应 | 生成详细、可编辑的执行计划，需你批准后才执行 | 结构化调试流程，自动分析错误日志、堆栈信息 | 自主思考、规划、执行、验证，形成“思考-行动-调试”闭环 |
| 最佳使用场景 | - 解释一段复杂代码<br>- 查询 API 用法（如“React 中 useEffect 依赖数组怎么用？”）<br>- 讨论技术选型 | - 重构前设计方案<br>- 大型功能开发前规划（如“添加用户权限系统”）<br>- 代码审查 | - 调试运行时错误（如“ReferenceError: xxx is not defined”）<br>- 定位性能瓶颈<br>- 分析崩溃日志 | - 实现完整功能（如“创建一个 Next.js 项目，集成 Tailwind 和 MongoDB”）<br>- 批量重构（如“将所有 class 组件改为函数组件”）<br>- 项目初始化 |

如何选择？

- 想快速问个问题，怕搞乱代码？ → 用 Ask  
  *“这段正则匹配什么？”“Python 装饰器怎么用？”*

- 要干一件大事，但不敢直接让 AI 改？ → 用 Plan  
  *“帮我规划一下如何把项目从 JavaScript 迁移到 TypeScript。”*

- 程序跑起来了，但报错了，找不到原因？ → 用 Debug  
  *“这个函数为什么返回 null？”“页面加载慢，哪里是瓶颈？”*

- 需求清晰，想让 AI 从头到尾搞定？ → 用 Agent  
  *“给整个项目加上 TypeScript 类型。”“实现一个用户登录功能，包括前端和后端。”*  
  ⚠️ 重要提醒：Agent 权限极高，务必在 Git 分支上使用，并先提交代码，避免误改导致项目崩溃。

工作流建议

一个高效的开发流程通常是：  
Ask（理解）→ Plan（设计）→ Agent（执行）→ Debug（修复）

例如，开发一个新功能：
1. 用 Ask 了解项目现有架构；
2. 用 Plan 与 AI 讨论并确认实现方案；
3. 用 Agent 自动化实现代码；
4. 如果出错，立即切换到 Debug 模式定位并修复。

> 一句话总结：Ask 是“问”，Plan 是“想”，Debug 是“查”，Agent 是“做”。不是越高权限越好，而是根据任务复杂度和风险，选择最合适的档位。
